## Process model

```
proot (supervisor)
 ├─ main thread ........ ptrace tracer: seccomp-trace stops for execve, chdir,
 │                        chroot, bind, connect, inotify_add_watch, O_PATH opens
 └─ notify-N threads ... leader/followers pool answering user notifications for
                          every other path syscall
tracee tree ............ one seccomp filter, installed by the first child
```

The first child installs the filter with the new-listener flag, passes the
listener descriptor back over a socketpair and waits for a byte. The parent
seizes it with ptrace, starts the pool and sends the byte. From then on every
traced syscall of every descendant has a supervisor.

## Why a small warm pool

The kernel hands a notification to the longest-waiting receiver. On an idle
host that is a cold core, and the wake-up costs more than the work. One thread
waits at a time and spins briefly first; whoever grabs the token next is
already warm. The spin budget decays to zero when requests stop arriving.

## Path translation

A guest path is walked one component at a time. Each component's host
counterpart is `lstat`ed; a symlink is read and its target re-entered as a
guest path, so a link inside the rootfs can never escape it. Relative paths
are resolved against the tracee's directory descriptor by reading its path
from `/proc`. A directory cache skips one `lstat` per component.

## execve

The kernel resolves `PT_INTERP` itself, which would escape the guest, so the
exec is retargeted at the host path of the guest's dynamic loader with the
program as its argument. Both glibc and musl loaders accept `--argv0`, so the
program sees the name it was called by. 32-bit programs go to the 32-bit
loader. The program the tracee asked for is recorded so `/proc/<pid>/exe`
answers truthfully.

## Staying invisible

A ptrace supervisor is indistinguishable from a debugger unless it works at
it. `/proc/<pid>/status` is served with `TracerPid` zeroed; an `int3`
breakpoint is resumed past as a debugger would, while a real crash sequence
(`int3; ud2`) still dies on the `ud2`; `/proc/<pid>/fd/N` links are left for
the kernel to re-open, since they name memfds, pipes and deleted files that
have no path. Tracees are seized so group-stops are distinguishable from
signals and job control keeps working.
