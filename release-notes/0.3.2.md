# proot-next 0.3.2

## Fixes

- A program that clears its dumpable flag with `prctl(PR_SET_DUMPABLE, 0)`
  is still served. The kernel closes a non-dumpable process's memory and
  `/proc/<pid>/fd` to a supervisor without `CAP_SYS_PTRACE`, so every path
  syscall after it failed with `EACCES`: Bitwarden's process isolation does
  this at start-up, and the client could neither open its log nor create a
  thread. The `prctl` is now answered without clearing the flag, and
  `PR_GET_DUMPABLE` reads back what the program set.
- A binding whose guest path goes through a symlink of the rootfs is now
  registered under the canonical path, the one lookups resolve to. On a
  merged-usr host `/lib` is a symlink to `usr/lib`, so a loader bound at
  `/lib/ld-linux.so.2` was never found: Steam's 32-bit reaper, which the
  client runs for its install-script evaluator outside any launch shell,
  failed to execute and Proton games never got their DirectX redistributable
  (Skyrim SE played menu sounds but no voices or music, since Wine's own
  XAudio2 has no xWMA decoder without it).
- A nested bwrap bind now carries the outer launch's bindings beneath its
  source along, as a recursive bind mount carries submounts. pressure-vessel
  binds the host `/` at `/run/host` and, seeing a 32-bit loader bound at the
  host's `/usr/lib/ld-linux.so.2`, symlinks the container's
  `/lib/ld-linux.so.2` to it; the dangling link left every 32-bit program in
  the game container unable to execute (Castle Crashers failed to launch).
- An exec whose argument or environment entry is longer than a path (4095
  bytes) is no longer refused with `ENOSYS`. Arguments and environments were
  read with the path reader, so a long `sh -c` script.
  Read up to the kernel's own limit for one such string.
