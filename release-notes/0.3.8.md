# proot-next 0.3.8

## Fixes

- An empty path is refused with `ENOENT`, as the kernel refuses it. It named
  the working directory, so `unlink("")` failed with `EISDIR`, `stat("")`,
  `open("")` and `chdir("")` succeeded on it, and `mkdir("")` said `EEXIST`.
  CUDA's driver unlinks `""` before it binds its abstract socket and gave up
  on the `EISDIR`, so `cuInit` failed and NVIDIA's Vulkan driver then refused
  every device with `VK_NVX_binary_import`. The calls the kernel lets an empty
  path name a descriptor with keep doing so: `AT_EMPTY_PATH` (`faccessat2`,
  `fchmodat2`, `execveat`) and `readlinkat`, with `AT_FDCWD` naming the
  working directory. `execveat(fd, "", AT_EMPTY_PATH)` of a `#!` script now
  runs it in the ptrace tier too.
- A `/proc/<pid>/ns` link is left to the kernel. The walk re-entered the
  link's content, `pid:[n]`, as a path, so a stat through `/proc/<pid>/ns/pid`
  failed with `ENOENT`; CUDA's driver reads that inode to name a socket.
- Without ptrace, an `O_PATH | O_NOFOLLOW` open of a symlink by a bare name
  reaches the link itself (#7). An `O_PATH` descriptor cannot be injected in
  that tier, so the path is rewritten in place to a transient alias, and the
  only form that stops at a symlink, `<alias>/<name>`, is two bytes longer
  than a bare name, which failed with `ENAMETOOLONG`. Such a name is now
  reached through a hard link to the link, the same inode, made in the alias
  directory when that is on the link's mount and otherwise through a staging
  directory created on it; the link is removed once the path is consumed, and
  `readlinkat` with an empty path on the descriptor is answered from the
  inode. The open still fails with `ENAMETOOLONG` where no hard link can be
  made: a read-only mount, no writable directory on it, another owner's link
  under `fs.protected_hardlinks`, or a name of one or two characters off the
  alias directory's mount. The analysis is solarex1's.
- Without ptrace, an `O_PATH | O_DIRECTORY` open of anything but a directory
  is refused with `ENOTDIR`, as it is natively. The flag was ignored, so `mv`
  over an existing file, which probes the destination that way and moves into
  it when the open succeeds, took a descriptor on the file, tried to rename
  into it and failed: `xdg-mime default` lost `~/.config/mimeapps.list` on
  every first run of a Qt proot-app. A path relative to a directory
  descriptor with nothing to translate is left to the kernel.
