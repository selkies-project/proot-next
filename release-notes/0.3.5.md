# proot-next 0.3.5

## Fixes

- A child process that reports its first stop before its parent's fork event
  waits for the event before it runs. Started at once, it could exec before it
  had a record of its own: the exec was planned in no view, and the event,
  arriving after, gave it the parent's record, so `/proc/self/exe` read as the
  parent's program. In a nested view, which every Steam container and
  proot-apps installer is, about one exec in a thousand did so. Only the
  ptrace tier was affected.
- `install-steam.sh` names proot-next once in its closing line.
