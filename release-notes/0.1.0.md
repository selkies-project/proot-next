# proot-next 0.1.0

The first release of PRoot reimplemented in Rust: `chroot` and bind mounts
without privilege, plus a bubblewrap front end, built for proot-apps and for
Steam's pressure-vessel in containers without user namespaces.

## How it works

- **seccomp user notification instead of ptrace stops** for every path syscall:
  a small pool of supervisor threads translates the path, performs the syscall
  and hands the result or an injected descriptor back. Only `execve`, `chdir`,
  `chroot`, unix-socket `bind`/`connect`, `inotify_add_watch` and `O_PATH`
  opens take a ptrace stop. Everything else runs untraced at native speed.
- **Adaptive supervisor pool**: spinning only while requests arrive in bursts,
  idle otherwise.

## Features

- **proot-apps compatible command line**: `-R`, `-r`, `-b`, `-w`, `-k`,
  `--kill-on-exit` (always on), `-v`.
- **Fake root** (`-0`, `-S`): a virtual identity per process with the
  kernel's rules for dropping it, forgiven `chown`/`mknod`, root-owned stat
  results and `/proc` status. `apt-get install` works inside a rootfs.
- **bwrap mode**: invoked through any name ending in `bwrap`, speaks
  bubblewrap 0.9's command line; pressure-vessel's option set works, including
  read-only binds (`EROFS`), `--args`, `--seccomp`, `--info-fd` and
  `--json-status-fd`. Namespace, uid and capability options are no-ops.
- **x86_64 and i386 tracees** on x86_64 hosts, **aarch64 and 32-bit ARM
  tracees** on aarch64 hosts.
- **Transparent to debugger detection**: `/proc/<pid>/status` hides the tracer,
  `int3` breakpoints resume as a debugger would, `/proc/<pid>/fd/N` links are
  re-opened by the kernel.
- **Static binaries** for x86_64 and aarch64, no runtime dependencies.
