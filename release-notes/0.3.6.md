# proot-next 0.3.6

## Fixes

- A mount point of the view (the root or a binding) opens with `O_NOFOLLOW`.
  Such an object is opened through the pinned descriptor's `/proc/self/fd`
  link, and the caller's flag was passed along, so the kernel refused the
  link with `ELOOP`. libpulse opens `PULSE_RUNTIME_PATH` that way before it
  connects, and proot-apps binds that directory at its own name, so no
  application in a proot-app reached the sound server: Chrome played video
  without sound. `openat2` with `RESOLVE_NO_SYMLINKS` or
  `RESOLVE_NO_MAGICLINKS` on a mount point, and an `O_PATH` open of one in
  the mode without ptrace, which failed with `ENOTDIR`, are served the same
  way.
